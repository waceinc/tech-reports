# Known limitations of the gate described in TR-2026-01 (as of run 13, commit 8327000 — report v1.3)

These are the limitations the report itself states. They are listed here so that the repository carries the same "known limitations" text as the report. The v1.0 version of this file (run 6) contained a factual error in item 1; see [ERRATA.md](ERRATA.md).

1. **Person-exposure false passes remain at 4** (of 19 false passes in 278 hazardous commands under a stale replica). All four are writes made while a timer preset had been changed in the plant program only. Rule changes do not close them; only a program-signature check can see them. **Person-exposure protection is therefore not claimed for the Modbus configuration.**
2. **Behavioral equivalence cannot see dormant program changes.** A change that has not yet produced behaviour does not appear in behaviour. A static program-signature check must precede any behavioral check.
3. **On Modbus there is no program signature**, so the gate cannot see this class of change on that protocol; PLC write protection and change management (including updating the gate's replica) must be in place. Program-signature readers for physical PLCs (MELSEC MC, LS XGT) are not implemented yet.
4. **The gate may block safe-direction commands.** 0 of 94 stop/de-energise commands were blocked in run 13 (2 in run 6), but a stop command the gate cannot judge — for example while its replica is unconfirmed or while the PLC is halted — is refused. Category safety stops must be wired around the gate.
5. **A halted PLC is recognised only through a scan counter.** The PLC program must carry a two-rung scan counter placed where no conditional jump, subroutine or interrupt can skip it; without it the gate cannot tell a halted PLC from an idle one. The probe window (80 ms in the experiment) must be at least twice the PLC's measured maximum scan time. A halted simulated PLC clears its outputs; a physical PLC may hold them, depending on a parameter.
6. **A sub-second input change can hold the gate in suspicion** (16 of 25 live-staged rows blocked at 0.07–0.3 s hold, measured on the run-6 tree and not re-measured); the recovery interval has a lower bound of 8 s and no upper bound, and has not yet been measured.
7. **Three hazard kinds (34 test commands) are confirmed unblockable** by the gate: remote reset, remote acknowledge (the gate cannot tell a supervisory write from an operator press) and 32-bit setpoints written as two words.
8. **Scope of evidence**: simulated PLC assembled from product components, three self-authored ladders (6, 19 and 21 rungs), one machine, no externally authored program, no physical PLC comparison, labels assigned by the team that built the gate.
