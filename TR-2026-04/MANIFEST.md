# TR-2026-04 release bundle - MANIFEST

WACE Technical Report TR-2026-04 (v1.0, 2026-10-02). This folder is `TR-2026-04/` of the repository github.com/waceinc/tech-reports and is also the content of the Zenodo record's release bundle. Round tr04-official-1: 147 generation units (G1 63, G2 63, G3 21), 146 judged, 462 plant-connected runs of judge (3) plus 11 baseline runs; simulated PLC engine and simulated plant model, 0 physical comparisons. Every file below is at most 5 MB, so every file is in the repository as well as in the Zenodo record (the publication plan keeps files above 5 MB in the Zenodo record only; there are none in this bundle).

## Public scope

Released: the pre-registration v0.4 and Amendment 1 (byte-identical), the task list, the task-bundle hash list, the three task specifications (cell A, cell B, pack cell), the three input-forcing test sets (62 tests) and their writing guide, the G3 model record, the eleven fixed code files as run (`code/`, nine as in pre-registration section 14 and two as changed by Amendment 1) and the two files as they were before Amendment 1 (`code/pre-amendment-1/`), the generated ladders as public versions, the judging records of all 146 judged units and the three baselines, the generation records of all 147 units, the analysis and leak-check scripts with their outputs, the two separate recounts and the run record (public versions), the decisions about the study, and Figure 1. In `sensitivity/`: a sensitivity analysis added after the results (decision K11) that judges the 8 G3 answers written after their units had ended; it is post hoc and not the main metric.

Not released (SHA-256 only, or listed): the appendix v2, which lists the instructions the PLC engine accepts (`TR-04_부록_엔진지원명령_v2.md`, SHA-256 `cabe4dacc3673122abe722359b781a4874e8fcfa17ca20b8d97b6d1d539eb512`, pre-registration section 14; it is also the `appendix.md` of every task folder) and every file that contains its text: the 63 G2 (Codex CLI) generator logs, whose session headers are given in `runs/tr04-run-1_g2_session_headers.tsv`. Every candidate file was screened for appendix text (each appendix line of 16 or more characters, and each 30-character stretch of it that holds Korean text, also after undoing JSON escapes); only the appendix copies and the G2 logs matched. Also not released: the tick traces of cells B and pack (442 files, 56,392,738,552 bytes uncompressed) and of the sensitivity round (6 files), the assembled ladders of the generation folders (they hold the engine's marker string and are byte-identical to the judged ladders, which are released as public versions), the generator CLI's tool state and the isolation probe files, the contents of the 32 set-aside unit folders (listed in `runs/tr04-run-1_set_aside.tsv`), except the completion record of T07-G3-r2, cited by the report and released as `runs/tr04-run-1_set_aside_T07-G3-r2_unit.json`, the PLC simulator engine, the engine host, the plant-model program and the test-bench runner beyond what TR-2026-02 and TR-2026-03 released, and the private configuration used to build this bundle. Every file left out of an archive is listed in a `*_not_released.tsv` with its size and SHA-256. No screen capture or video of the company's 3D viewer is in this bundle; the round folder holds none.

The engine marker string (the top-level `marker` value the engine's parser requires) occurs in no file of this bundle, including every archive member: the judged ladders are released with that line removed by the pre-registered conversion (`ladders/공개본_변환.py` of TR-2026-03), and the fixed code reads the string from the local configuration.

## Path redaction

Files that contained absolute local paths are released as public versions in which five local absolute directory prefixes (the document folder, the generation working folder, the run folder, the repository folder and the model folder) are replaced by `<docs>`, `<work>`, `<run>`, `<repos>` and `<models>`. No other byte changes. `scripts/redact_pack.py` does the replacement, refuses input that already contains a placeholder and checks for every file that restoring the prefixes gives back the original bytes. The prefixes are ordinary local paths; they are replaced to keep machine paths out of the files, not because they are secret. Original SHA-256 values are given per archive member in the `*_files.tsv` files. The OS temporary-folder paths `/private/tmp` and `/private/var/folders` in both versions of `isolate.py` are system paths shared by every macOS user, written into the sandbox profile; they hold no user name and are kept. The pre-registration v0.4 contains an internal host name as plain text (a search term of its public-safety check, not a URL); its hash is fixed, so it is released as written. The four records in `results/` marked "public version" had paths written by hand in prose and code; those were replaced by named placeholders (listed in their rows) and their original SHA-256 is given below. Names of private repositories remain in the pre-registration and the task list (hashes fixed), in run metadata, static-check and input-forcing records (as part of redacted paths and commit lists) and in the run record; none is a URL. OS paths without a user name remain where a program wrote them (`/private/tmp` and `/private/var/folders` in both versions of `isolate.py`; the Homebrew Python path in seven G3 generator logs; `/tmp/claude-501` in the run record, as quoted in the report).

Search of this bundle (all files, every member of the six archives, PNG text chunks) for local absolute paths below the home directory, the home-relative prefix (tilde and slash), cloud-sync folder names, the local user name, the machine name, an internal host name, a personal e-mail domain, the engine marker string and appendix text: no match except the home-relative prefix in the pre-registration and Amendment 1 (tool-state folders, hash fixed), the search terms named in the pre-registration's public-safety row (hash fixed), the home-directory root as a search pattern inside `scripts/redact_pack.py`, an ordinary English word equal to the user name in the report, and two bytes of compressed image data in the PNG. A positive control with each search term placed in a plain file, an archive member, a JSON-escaped string and a PNG text chunk was found by the same search before it was run on the bundle.

## Reproducing the checks

```
mkdir x && cd x
for c in cell-a cell-b cell-b-pack; do tar -xJf ../runs/tr04-official-1_$c.tar.xz; done   # -> tr04-official-1/
tar -xJf ../runs/tr04-run-1_generation.tar.xz                                              # -> work/
python3 ../scripts/TR-04_분석.py tr04-official-1 work            # = ../results/TR-04_분석_출력_2026-10-02.txt
# correct ladders from TR-2026-03 (../../TR-2026-03/ladders/<cell>__correct.program.ldprog.json) laid out as lad/<cell>/correct/program.ldprog.json
python3 ../scripts/TR-04_누출검사.py ../tasks/TR-04_과제목록_v1.json lad work   # = ../results/TR-04_누출검사_출력_2026-10-02.txt
python3 ../scripts/make_figures.py .. tr04-official-1 work out/   # SVG + PNG (PNG if rsvg-convert is installed)
tar -xJf ../ladders/tr04-official-1_ladders_public.tar.xz        # -> ladders/ (public versions)
tar -xJf ../sensitivity/tr04-sens-late-1.tar.xz                  # -> tr04-sens-late-1/ (post hoc, not the main metric)
```

Both outputs were reproduced byte for byte from the extracted archives on the author's machine, without the appendix: the leak check reads the appendix only to mark whether a matching string also occurs in the task folder, and none of the 1,135 matches occurs in the appendix alone. The leak check's late-file rule compares the modification time of `out/blank.json` with the completion time in `unit.json`; the generation archive keeps the original modification times in whole seconds, which gives the same 8 late files. `make_figures.py` gave byte-identical SVG, PNG and figure_values.json in two runs here; PNG pixels depend on the renderer and installed fonts. Badge (Korean): "시뮬레이션 · 실물 대조 0" (simulation · 0 physical comparisons) and "© WACE · CC BY 4.0". The pre-registration's other two figures (the moment a ladder that passed (1) and (2) fails (3), and the cause classes) cannot be drawn, because no ladder failed (3) alone.

No run can be re-executed from this bundle: the judges (1) and (2) and the judge (3) runner need the private PLC simulator engine and plant model.
