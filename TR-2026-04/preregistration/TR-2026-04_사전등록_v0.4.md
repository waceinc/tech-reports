## 1. 질문

LLM 이 사양서만 보고 만든 래더가 **① 정적 검사**와 **② 입력 강제 시험**을 통과한 뒤 **③ 공장 모형 연결 실행**에서 몇 %가 틀리는가. 원인은 무엇인가.

## 2. 왜 가상으로만 의미가 있나

세 판정이 같은 래더·같은 모형을 본다. 묻는 것은 판정 방법끼리의 검출력 차이다. 빈자리: SemaPLC(2026-08)는 공정 모사 없이 변수를 강제했고, 가상 시운전 고찰(2026) 243 편에 AI 생성 PLC 코드 검증 0 건(`92_기술참조/기술_AI시대PLC_깹TV_영상분석_2026-09-24.md` §4).

### 6-4. `marker` 처리 규칙

- 엔진의 프로그램 파서는 최상위 키를 엄격하게 검사하고 `format` · `schemaVersion`(1) · `marker`(정해진 문구) · `name` · `engine` · `tags` · `rungs` 를 필수로, `description` · `semanticProfile` · `fbInstances` 를 선택으로 받는다. 그 밖의 키는 오류다. 태그 이름·주소가 겹쳐도 오류다(plc-simulator `b415c25` `packages/scenario/src/program/schema.ts`·`parse.ts`). 실행기는 여기에 더해 `engine.logicalDtUs` = 10,000 을 요구한다.
- **생성기에게는 `marker` 를 쓰지 말라고 한다**(부록 v2 §1, `TASK.md`). 판정기(`tr04/assemble.py`)가 받은 파일의 `marker` 를 지우고 `schemaVersion` 바로 뒤에 엔진 문구를 넣는다. 문구는 로컬 설정에만 있고 공개 코드에 없다. 생성기가 `marker` 를 썼는지와 그 값은 기록한다. 나머지 필수 키는 생성기 몫이다 — 빠지거나 틀리면 ① S1 [FAIL](수정 기회 대상).
- 빈칸 과제는 `base` 에 산출 렁을 끼우고, 산출 태그를 `base` 태그 뒤에 붙인 뒤 같은 규칙으로 `marker` 를 넣는다. 정답 블록을 산출물로 넣으면 정답 래더와 렁·태그·키 순서까지 같다(21/21).

## 7. 오염 차단 — 격리 (⑥ 채움)

- `tr04/isolate.py`: macOS `sandbox-exec` 프로필 = 기본 허용 + **읽기·쓰기 차단 폴더**(레포 폴더 전체 · 업무 폴더 전체 · 결과 폴더 — 정답 래더·시나리오·판정 기준·다른 단위 결과가 모두 여기에 있다) + 작업 폴더·도구 상태 폴더(`~/.claude` 등)·임시 폴더 밖 쓰기 차단 + (G3) localhost 밖 네트워크 차단.
- **매 실행 전 자체 점검**(하나라도 [FAIL] 이면 생성하지 않는다): 대조로 샌드박스 밖에서 차단 폴더 안 파일이 읽히는지 → 샌드박스 안에서 그 파일 읽기 막힘 · 그 폴더 목록 막힘 · 작업 폴더 쓰기 됨 · 작업 폴더 밖 쓰기 막힘.

## 11. 주장하지 않는 것

- 특정 LLM 의 PLC 능력 순위(생성기 3 · 과제 21).

- **생성형 AI 관여**: 하네스·래더·사양서·시험·부록·이 문안 작성에 LLM 코딩 에이전트가 관여했고, 독립 검수도 같은 계열 에이전트다.

- 공개 규칙은 v0.3 §13 그대로다(실행본·공개본, 해시 불변, K5 순서). 생성 래더와 기준 래더를 결과 파일로 공개할 때는 같은 공개본 변환(`고정입력/공개본_변환.py`)으로 `marker` 를 뺀다.
- 사양서·부록·시험의 공개 범위(대외비 엔진의 명령 목록 · 셀 동작 사양)는 결과 공개 전에 대표가 따로 정한다(v0.3 §13 과 같음).
