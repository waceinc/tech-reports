# 포장 셀 기능 사양서

## 1. 목적과 범위

이 문서는 포장 셀 PLC 프로그램의 기능 요구사항이다. 사양서만 읽고 래더를 작성할 수 있게 쓴다.

**정답 기준**: 이 셀의 정답 래더 동작(10 ms 스캔)이 정답이다. 참조 동작 모형과 정답 래더가 다른 곳은 모두 정답 래더를 따랐다.

포장 셀은 분류 셀(셀 B)과 그 뒤의 포장 설비를 한 PLC 로 제어한다. 포장 설비는 아래 5개 장치다.

| 장치 번호 | 장치 | 태그 접두 | 짝 |
| --- | --- | --- | --- |
| 1 | 로봇 1 | P.R0 | 케이스 교환기 1 |
| 2 | 로봇 2 | P.R1 | 케이스 교환기 2 |
| 3 | 케이스 교환기 1 | P.C0 | 로봇 1 |
| 4 | 케이스 교환기 2 | P.C1 | 로봇 2 |
| 5 | 토트 교환기(불량 토트) | P.Tote | 불량 슈트 버퍼 |

- 로봇 1은 케이스 라인 1(케이스 교환기 1)에, 로봇 2는 케이스 라인 2(케이스 교환기 2)에 상자를 담는다.
- 불량 상자는 불량 슈트 버퍼를 지나 토트에 모인다.
- 분류 셀 동작은 「셀 B 기능 사양서」를 따른다. 이 문서는 포장 셀에서 더해지는 것과 달라지는 것만 적는다.
- 포장 셀에서 분류 셀 동작이 달라지는 곳은 6절(PB-01 ~ PB-06)에 모두 적었다. 6절에 없는 분류 셀 동작은 셀 B 사양서와 같다.
- 이 문서의 B-xx 는 「셀 B 기능 사양서」의 요구사항 번호다.

## 2. 시간 기준

- PLC 는 10 ms 정주기로 스캔한다. 이 문서의 시간은 모두 스캔 수로 센다. 1 스캔 = 10 ms.
- 「N 스캔을 넘으면」은 N+1 번째 스캔에서 조건이 성립한다는 뜻이다. 예: 50 스캔을 넘으면 = 51 번째 스캔(510 ms).
- 스캔 계수는 분류 셀 쪽과 같은 셀 공용 스캔 계수를 쓴다. 전원 투입 뒤 첫 스캔의 계수는 1 이다.
- 입력은 스캔 시작에 읽고, 출력은 그 스캔 끝의 값이 다음 공장 주기에 적용된다.
- 에지 판단은 모두 「이번 스캔 입력」과 「직전 스캔 입력」을 비교한다. 직전 값은 허가 여부와 상관없이 매 스캔 갱신한다.
  - 상승: 직전 OFF, 이번 ON
  - 하강(뗌): 직전 ON, 이번 OFF
  - 첫 스캔의 직전 값은 모두 OFF 로 본다.

- 포장 셀의 분류 쪽 태그는 셀 B 태그표와 이름·주소·형식·뜻이 모두 같다. 새로 더해지는 분류 쪽 태그는 없다.

- 버퍼 여유 수 입력은 입출력 표에 없다. 투입 허가 조건에 버퍼 여유 확인을 넣지 않는다(P-25).

## 5. 동작 요구사항

### 5-1. 공통 용어

- **포장 고장**: 5절의 고장 조건 가운데 하나가 성립해 기억된 상태. 포장 고장은 한 번에 하나만 기억한다. 먼저 성립한 것이 첫 원인이다.
- **포장 안전 정지**: P.Safety.permit 이 한 번이라도 ON 이 된 뒤 OFF 가 되어 기억된 상태.
- **포장 허가**: P.Safety.permit ON, 포장 고장 없음, 포장 안전 정지 아님이 모두 성립.
- **격리 중**: P.Quarantine ON 이거나 P.Reject.reason 이 2.
- **신규 요청 허가**: 포장 허가이면서 격리 중이 아님.
- **장치 원인 활성**: 5개 장치의 fault 입력 가운데 하나라도 ON.

### 5-2. 핸드셰이크 (5개 장치 공통)

장치마다 아래 5단계 가운데 하나에 있다. 전원 투입 때는 모두 0 단계다.

| 단계 | 이름 | 기다리는 신호 | 출력 |
| --- | --- | --- | --- |
| 0 | 대기 | 요청 조건 | 없음 |
| 1 | 요청 | busy 상승 | request |
| 2 | 집기 대기 | picked 상승 | 없음 |
| 3 | 완료 대기 | done 상승 | 없음 |
| 4 | 확인 | done 하강 | ack |

- **P-01** 포장 허가가 아닌 스캔에서는 모든 장치의 단계가 그대로다. 단계 경과 스캔과 작업 스캔도 세지 않는다. 이 동안 들어온 에지는 버린다(직전 값은 계속 갱신).
- **P-02** 포장 허가인 스캔에서는 장치마다 단계 경과 스캔을 1 늘린 뒤 아래 전이를 판단한다. 한 장치는 한 스캔에 한 단계만 옮긴다.
- **P-03** 0 단계에서 요청 조건(P-10 · P-15 · P-18)이 성립하고 그 장치의 busy 와 done 이 모두 OFF 이면 1 단계로 옮긴다. 이때 단계 경과 스캔과 작업 스캔을 0 으로 한다. 로봇이면 같은 스캔에 레시피를 잡는다(P-11 ~ P-13).
- **P-04** 1 단계에서 busy 상승이 오면 2 단계로 옮기고 단계 경과 스캔을 0 으로 한다. busy 상승 없이 단계 경과 스캔이 50 을 넘으면 그 장치의 「busy 응답 없음」 고장이다.
- **P-05** 2 단계에서 picked 상승이 오면 3 단계로 옮기고 단계 경과 스캔을 0 으로 한다. picked 상승 없이 단계 경과 스캔이 100 을 넘으면 그 장치의 「집기·용기 이탈 확인 없음」 고장이다. 교환기의 picked 는 교체 용기(토트) 이탈 확인이다.
- **P-06** 3 단계에서 done 상승이 오면 4 단계로 옮기고 단계 경과 스캔을 0 으로 한다. 3 단계 자체에는 단계 경과 한도가 없다(작업 한도 P-08 만 본다).
- **P-07** 4 단계에서 done 이 OFF 이면(에지가 아니라 값) 0 단계로 옮기고 단계 경과 스캔을 0 으로 한다. done 이 ON 인 채 단계 경과 스캔이 50 을 넘으면 그 장치의 「완료 신호 하강 없음」 고장이다.
- **P-08** 전이 판단 뒤 장치가 2 단계 또는 3 단계이면 작업 스캔을 1 늘린다. 작업 스캔이 로봇은 630, 교환기(케이스 교환기 1·2, 토트 교환기)는 400 을 넘으면 그 장치의 「작업 시간 초과」 고장이다.
- **P-09** 단계 순서를 건너뛴 신호는 받지 않는다. 예: 2 단계에서 done 이 먼저 올라도 3 단계 전이로 치지 않고, picked 상승을 계속 기다린다.

### 5-3. 로봇 요청과 레시피

로봇 1(P.R0)은 케이스 라인 1(P.C0)과, 로봇 2(P.R1)는 케이스 라인 2(P.C1)와 짝이다. 아래 「도착 수」는 그 로봇의 available 입력이다.

- **P-10** 로봇 요청 조건은 아래가 모두 성립할 때다.
  - 신규 요청 허가
  - 로봇 ready ON, home ON, busy OFF, arrival ON
  - 짝 케이스 present ON, full OFF, busy OFF, done OFF
  - 도착 수가 4 이상, 또는 도착 수가 1 이상이고 P.Batch.complete ON
- **P-11** 요청 집기 수 = 도착 수를 0 ~ 4 로 자른 값. 요청 시작(0→1 단계) 스캔에 잡는다.
- **P-12** 활성 컵쌍 비트 = 요청 집기 수가 0·1·2·3·4 일 때 각각 0·1·3·7·15.
- **P-13** 적재 행은 요청 시작 스캔의 짝 케이스 count 로 잡는다. 계산은 정수 나눗셈 두 번이다.
  - 먼저 q = count ÷ 2 (몫은 0 쪽으로 버린다).
  - 적재 행 = q − (q ÷ 2, 0 쪽으로 버림) × 2.
  - count 가 0 이상이면 값은 0 또는 1 이다. count 가 음수면 이 계산 그대로 음수 결과(예: count −3 → −1)를 낸다.
- **P-14** 레시피 세 값(row·request_count·mask)은 요청 시작 스캔에 한 번 잡고, 다음 요청 시작까지 출력을 그대로 유지한다. 작업이 끝나 0 단계로 돌아가도 지난 값을 유지한다. 전원 투입 뒤 첫 요청 전에는 세 값 모두 0 이다.

### 5-4. 케이스 교환 요청

- **P-15** 케이스 교환기 요청 조건은 아래가 모두 성립할 때다.
  - 신규 요청 허가
  - 그 케이스 full ON
  - 짝 로봇 ready ON, home ON
- **P-16** 케이스가 만재이면 짝 로봇의 새 요청을 내지 않는다(P-10 의 full OFF 조건). 만재 케이스는 교환 요청으로만 처리한다.

### 5-5. 토트 교환과 불량 배출

- **P-17** 토트 교환기 요청 조건은 신규 요청 허가, P.Tote.full ON, P.Tote.settled ON 이 모두 성립할 때다.
- **P-18** 토트 교환기는 5-2 공통 규칙(P-01 ~ P-09)을 따른다. picked 는 교체 토트 이탈 확인이고, 작업 한도는 400 스캔이다.
- **P-19** P.Reject.gate(불량 슈트 버퍼 배출)는 아래가 모두 성립할 때만 ON 이다.
  - 신규 요청 허가
  - 포장 고장 없음(이번 스캔에 성립한 고장 포함)
  - P.Tote.present ON, P.Tote.busy OFF, P.Tote.done OFF, P.Tote.full OFF
  - P.Tote.count 가 4 미만

### 5-6. 요청·확인 출력

- **P-20** 각 장치의 request 는 신규 요청 허가, 포장 고장 없음(이번 스캔 성립분 포함), 그 장치가 1 단계, 이 셋이 모두 성립할 때 ON 이다.
  - 요청 시작 스캔에 바로 ON 이 된다.
  - busy 상승을 받은 스캔에 OFF 가 된다.
- **P-21** 격리 중에는 1 단계에 있는 장치도 request 를 끈다. 단계는 1 에 그대로 두고, 단계 경과 스캔은 계속 센다(포장 허가이므로). 그래서 격리가 길어지면 「busy 응답 없음」 고장이 날 수 있다.
- **P-22** 각 장치의 ack 는 핸드셰이크 처리 전에 정한 이번 스캔의 포장 허가(9절 8번, 이번 스캔 핸드셰이크에서 새로 성립한 고장은 반영하지 않음)와 그 장치가 4 단계인 것이 함께 성립할 때 ON 이다.
  - done 하강을 받은 스캔에 OFF 가 된다.
  - 격리 중에도 진행 중인 작업의 단계 전이와 ack 는 그대로 처리한다. 격리는 새 요청만 막는다.

### 5-7. 허가·투입·램프 출력

- **P-23** P.Safety.enable 은 포장 허가이고 포장 고장이 없을 때(이번 스캔 성립분 포함) ON 이다. 격리 중에도 ON 을 유지한다.
- **P-24** P.Feed.ready(분류 투입 허가)는 아래가 모두 성립할 때 ON 이다.
  - 신규 요청 허가
  - 포장 고장 없음(이번 스캔 성립분 포함)
  - P.C0 은 present 또는 busy, P.C1 은 present 또는 busy, P.Tote 는 present 또는 busy
- **P-25** P-24 에 버퍼 여유 조건을 넣지 않는다. 버퍼 여유 입력이 입출력 표에 없다(3-4).
- **P-26** P.Lamp.stock 은 P.C0.stockLow · P.C1.stockLow · P.Tote.stockLow 가운데 하나라도 ON 이고, 점멸 위상이 켜짐일 때 ON 이다.
  - 점멸 위상은 셀 B 사양서 B-81 의 「점멸 위상」과 같은 값이다. (셀 공용 스캔 계수 ÷ 50 의 내림 몫)이 짝수이면 켜짐, 홀수이면 꺼짐.
  - 첫 스캔(계수 1)부터 49 스캔까지 켜짐, 50 ~ 99 꺼짐, 100 ~ 149 켜짐을 되풀이한다.
  - 포장 허가·고장과 상관없이 동작한다.

### 5-8. 포장 고장

- **P-27** 장치 원인 활성: 장치 fault 입력이 ON 인 스캔마다 그 장치의 「장치 고장 원인 활성」 고장 조건이 성립한다. 조건 판단 순서는 로봇 1 → 로봇 2 → 케이스 교환기 1 → 케이스 교환기 2 → 토트 교환기다.
- **P-28** 핸드셰이크 고장(P-04 · P-05 · P-07 · P-08)은 장치 순서 로봇 1 → 로봇 2 → 케이스 교환기 1 → 케이스 교환기 2 → 토트 교환기로 판단한다. 한 스캔에 두 장치의 고장이 함께 성립하면 이 순서에서 앞선 장치가 첫 원인이다. 한 장치 안에서는 단계 고장(busy 응답·집기 확인·done 하강)을 먼저, 작업 시간 초과를 다음에 본다.
- **P-29** 포장 고장이 이미 기억돼 있으면 새 고장 조건은 기억하지 않는다. 첫 원인 코드를 바꾸지 않는다.
- **P-30** 한 스캔 안에서 고장이 성립해도 그 스캔의 나머지 장치 단계 전이는 핸드셰이크 처리 전에 정한 포장 허가(9절 8번)로 계속 처리한다. 다음 스캔부터 포장 허가가 꺼진다.
- **P-31** 포장 고장이 있으면(성립한 스캔 포함) 아래 출력을 모두 끈다.
  - 5개 장치의 request
  - P.Safety.enable, P.Feed.ready, P.Reject.gate
- **P-32** 포장 고장 해제는 아래가 모두 성립하는 스캔에서만 한다.
  - P.PB.reset 뗌 에지
  - P.Safety.permit ON
  - 장치 원인 활성 아님(5개 fault 입력 모두 OFF)
  - 포장 고장이 있거나 포장 안전 정지 중
- **P-33** 해제 스캔에 하는 일:
  - 포장 고장 기억을 지운다.
  - 리셋 확인 상태를 켠다(P-36 에서 쓴다).
  - 5개 장치 모두 단계 경과 스캔과 작업 스캔을 0 으로 한다.
  - 1 단계(요청)가 아니고 busy·done 이 모두 OFF 인 장치는 0 단계로 되돌린다.
  - 1 단계 장치는 1 단계를 유지한다. busy·done 가운데 하나라도 ON 인 장치는 단계를 유지한다(동작 중인 작업을 버리지 않는다).
  - 해제 판단은 같은 스캔의 장치 단계 전이보다 먼저 한다.

### 5-9. 포장 안전 정지와 재기동

- **P-34** P.Safety.permit 이 한 번도 ON 이 된 적이 없으면 포장 안전 정지를 기억하지 않는다. 이 동안은 포장 허가가 아니므로 모든 요청·확인·허가 출력이 꺼져 있다.
- **P-35** P.Safety.permit 이 한 번이라도 ON 이 된 뒤 OFF 가 되면 그 스캔부터 포장 안전 정지를 기억하고 리셋 확인 상태를 끈다. permit 이 다시 ON 이 되어도 저절로 풀리지 않는다.
- **P-36** 포장 안전 정지는 아래가 모두 성립하는 스캔에서 풀린다(재기동).
  - P.Safety.permit ON
  - 리셋 확인 상태 ON(P-32 해제로 켜진다. 같은 스캔에 켜진 것도 인정)
  - P.PB.start 상승 에지
  - 포장 고장 없음
  - 장치 원인 활성 아님
- **P-37** 재기동 스캔에 리셋 확인 상태를 끈다. 리셋만으로는 포장 안전 정지가 풀리지 않는다. 리셋 뒤 기동을 따로 눌러야 한다.
- **P-38** 포장 안전 정지 중에도 포장 고장 코드와 장치 단계는 유지한다.

### 5-10. 장치 리셋 펄스

- **P-39** 5개 장치의 reset 출력(P.R0.reset · P.R1.reset · P.C0.reset · P.C1.reset · P.Tote.reset)은 같은 값이다. 아래가 모두 성립하는 스캔에 1 스캔만 ON 이다.
  - P.Safety.permit ON
  - 장치 원인 활성 아님
  - 그 스캔 처리 뒤 포장 안전 정지 아님
  - 이번 스캔에 포장 고장 해제(고장이 있던 경우)가 있었거나 재기동이 있었다
- **P-40** 포장 안전 정지 중에 리셋만 누른 경우에는 장치 리셋 펄스를 내지 않는다. 뒤이은 재기동 스캔에 낸다.

### 5-11. 포장 고장 장치 번호·코드

- **P-41** P.HMI.faultCode 는 기억된 포장 고장의 첫 원인 코드(7절)다. 고장이 없으면 0 이다.
- **P-42** P.HMI.faultDevice 는 첫 원인 장치 번호다.
  - 고장 없음 0, 로봇 1 은 1, 로봇 2 는 2, 케이스 교환기 1 은 3, 케이스 교환기 2 는 4, 토트 교환기는 5, 아래 코드 범위에 들지 않는 고장은 6.
  - 장치 번호는 코드 범위로 정한다: 101~105 → 1, 111~115 → 2, 121~125 → 3, 131~135 → 4, 141~145 → 5.
  - 7절 코드는 모두 이 범위에 들므로 지금 코드표로는 6 이 나오지 않는다.
- **P-43** 두 워드는 고장이 성립한 스캔에 바로 값이 들어가고, 고장 기억 동안 유지하며, 해제(P-32) 스캔에 0 이 된다.

## 6. 분류 셀 동작이 포장 셀에서 달라지는 곳

- **PB-01 배치 수량** 포장 셀에서는 분류 쪽 배치 완료 수량을 20 이 아니라 60 으로 한다.
  - 투입 수가 60 에 이르면 배치 완료를 기억한다.
  - 셀 B 사양서 B-35 의 「투입 수가 20 이상이면 배치 완료」와 매개변수 표의 배치 수량 20 을 60 으로 읽는다.
  - 배치 완료 뒤의 사이클 정지, 기동 거부(B-07), 배치 확인 뗌으로 하는 계수 초기화(B-53)는 셀 B 사양서와 같다.
  - 분류 셀 동작 가운데 값이 달라지는 곳은 이것 하나다.
- **PB-02 포장 준비 입력의 출처** 포장 셀에서 B.Pack.ready(X28)에는 이 PLC 의 출력 P.Feed.ready(Y80)가 외부 배선으로 들어온다. 출력이 입력으로 돌아오므로 한 스캔 늦다.
  - 분류 쪽은 셀 B 사양서대로 B.Pack.ready 입력을 읽는다. 내부 값으로 바꿔 읽지 않는다.
  - 셀 B 사양서의 B.Pack.ready 처리가 그대로 적용된다. 정지·기동 예고 중이면 기동 조건 불충족(B-07 · B-08 · B-09)이고, 운전 중이면 사이클 정지 요청(B-51)이다.
  - 그래서 아래 포장 상태는 모두 분류 셀의 기동 거부 또는 사이클 정지를 부른다.
    - 포장 고장
    - 포장 안전 정지
    - 격리 중
    - 케이스 1·2 나 토트가 제자리에 없고 교환 중도 아님
    - P.Safety.permit 이 아직 한 번도 ON 이 되지 않음
  - 전원 투입 첫 스캔에는 Y80 이 OFF 이므로 B.Pack.ready 도 OFF 로 들어온다.
- **PB-03 투입 허가 조건** P.Feed.ready 는 P-24 의 조건으로만 정한다. 분류 쪽 운전 상태는 이 조건에 들어가지 않는다.
- **PB-04 안전의 분리** P.Safety.permit 은 셀 B 안전 허가와 포장 커튼 허가를 외부 배선에서 AND 한 입력이다.
  - 포장 쪽은 분류 쪽 안전 입력(B.PB.estop_nc, B.Safety.curtain)을 직접 읽지 않는다.
  - 분류 쪽 비상정지·커튼 차단이 일어나면 P.Safety.permit 도 OFF 가 되어 포장 안전 정지가 된다.
  - 복귀할 때 분류 쪽은 B.PB.reset·B.PB.start 로(셀 B 사양서), 포장 쪽은 P.PB.reset·P.PB.start 로(P-32 · P-36) 따로 복귀한다. 한쪽 버튼이 다른 쪽을 풀지 않는다.
- **PB-05 벨트 구동 배선 전제** P.Safety.enable(Y6D)이 OFF 이면 외부 배선이 주 컨베이어 전진 구동을 끊는다. 이때는 B.Conv.run 이 ON 이어도 벨트가 돌지 않는다. PLC 의 분류 쪽 동작은 바꾸지 않는다. 정답 래더에도 이 상황만을 위한 분류 쪽 처리는 없다. 벨트가 멈춘 뒤의 분류 쪽 감시 반응은 셀 B 사양서를 따른다.
- **PB-06 램프 위상 공유** P.Lamp.stock 의 점멸은 분류 쪽 점멸 표시(행정 경고 표시등, 녹색등 점멸)와 같은 셀 공용 스캔 계수·같은 위상을 쓴다(P-26).
- 위 6가지 말고는 포장 쪽 상태가 분류 쪽 기동·정지·안전·투입에 끼어들지 않는다. 분류 쪽 출력과 HMI 워드(B.HMI.*)는 셀 B 사양서와 같다.

## 9. 우선순위와 같은 스캔 처리 순서

한 스캔 안에서 아래 순서로 판단한다. 뒤 단계는 앞 단계의 결과를 쓴다.

1. 셀 공용 스캔 계수를 1 늘린다(분류 쪽과 공용).
2. 분류 쪽 동작을 셀 B 사양서대로 처리한다. 포장 쪽과는 입력 B.Pack.ready 로만 연결되므로 분류 쪽과 포장 쪽의 처리 앞뒤는 결과에 영향이 없다.
3. 포장 버튼 에지를 판단한다(P.PB.reset 뗌, P.PB.start 상승).
4. 장치 원인 활성 고장(P-27)을 판단한다.
5. 포장 안전 정지를 판단한다(P-34 · P-35). 그다음 permit ON 이면 「permit 이 한 번 ON 이 됨」을 기억한다.
6. 포장 고장 해제(P-32 · P-33)를 판단한다.
7. 재기동(P-36)을 판단한다.
8. 포장 허가와 신규 요청 허가를 정한다. 이 값은 이 스캔의 나머지 단계에서 바꾸지 않는다.
9. 장치 핸드셰이크(P-01 ~ P-18)를 로봇 1 → 로봇 2 → 케이스 교환기 1 → 케이스 교환기 2 → 토트 교환기 순서로 처리한다. 장치마다 단계 경과 스캔 증가 → 전이 또는 단계 고장 → 작업 스캔 증가 → 작업 시간 초과 순서다.
10. 출력을 정한다(P-19 ~ P-26). ack 는 8번의 포장 허가로 판단한다. request·P.Safety.enable·P.Feed.ready·P.Reject.gate 는 9번까지 성립한 고장을 반영해 끈다(P-31).
11. 장치 리셋 펄스(P-39)를 정한다.
12. 포장 HMI 워드(P-41 ~ P-43)를 쓴다.
13. 이번 스캔 입력을 직전 값으로 기억한다.

우선순위 요약:

- 포장 고장이 있으면 요청·구동 허가·투입 허가·불량 배출이 모두 꺼진다. 다른 어떤 조건보다 앞선다.
- 포장 안전 정지는 리셋과 기동을 따로 받아야 풀린다.
- 격리는 새 요청과 투입 허가·불량 배출만 막는다. 진행 중인 작업의 완료·확인과 구동 허가는 막지 않는다.
- 첫 원인 고장 코드는 해제 전까지 바뀌지 않는다.
