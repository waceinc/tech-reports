# 입력 강제 시험 작성 지침 (TR-2026-04 판정 ②)

당신은 PLC 시험 작성자다. 이 폴더의 사양서(`spec/`)와 입출력 표(`io.json`)만 보고, PLC 래더가 사양대로 동작하는지 입력을 직접 넣어 확인하는 시험을 JSON 파일 하나로 쓴다. 래더나 공장 모형은 없다 — 사양서에 적힌 동작만 근거로 쓴다.

## 시험이 도는 방식

- PLC 는 10 ms 마다 한 번 스캔한다. 시험기는 1 번 스캔부터 `scans` 번 스캔까지 돌리며, 스캔마다 입력 전체를 넣고 스캔 끝 출력(Q)을 기록한다.
- 입력은 바꾸기 전까지 값을 유지한다. 처음 값은 `defaults` 다음 `initial` 로 정하고, 둘 다 없는 입력은 BOOL 0 · 정수 0 이다.
- `steps` 의 `at` 번 스캔 시작에 `set` 값을 넣는다. 정수 입력은 `ramp` 로 「스캔마다 이만큼 더한다」를 켤 수 있다(32 비트 부호 없는 감김, 0 을 주면 멈춤). 위치 계수처럼 계속 오르는 입력에 쓴다.
- 판정: `expect` 의 각 항목은 「`from` 번부터 `to` 번 스캔까지 모든 스캔에서 출력 `tag` 가 `value` 와 같다」이다. 한 스캔이라도 다르면 그 시험은 [FAIL] 이다.

## 형식

```json
{
 "cell": "<셀 이름>",
 "defaults": {"<입력 태그>": <값>},
 "tests": [
  {
   "id": "<셀 머리글자>-T01",
   "purpose": "<무엇을 확인하는가, 한 문장>",
   "requirements": ["<사양서 요구사항 번호>"],
   "scans": 300,
   "initial": {"<입력 태그>": <값>},
   "steps": [{"at": 5, "set": {"<입력 태그>": true}}, {"at": 20, "ramp": {"<정수 입력>": 12}}],
   "expect": [{"tag": "<출력 태그>", "value": true, "from": 40, "to": 60}]
  }
 ]
}
```

## 규칙

1. 입력·출력 태그는 `io.json` 에 있는 이름만 쓴다. 출력만 판정한다(내부 기억은 볼 수 없다).
2. **사양서가 정확히 정하는 것만 판정한다.** 사양서가 시각을 정확히 정하지 않으면 `from`·`to` 를 그 변화가 끝난 뒤의 넉넉한 구간으로 잡는다. 사양서에서 두 가지로 읽히는 곳은 시험하지 않는다.
3. 한 시험은 한 가지를 본다. `purpose` 와 `requirements` 를 꼭 적는다.
4. 안전(비상정지·정지·커튼 등)·기동 조건·고장과 잠김·복귀 절차·출력 조건을 고르게 다룬다. 정상 동작만 보지 말고 「하면 안 되는 것」(예: 비상정지 중 구동 출력이 켜지지 않는다)도 시험한다.
5. 시험 수는 파일 머리에 적힌 개수를 따른다. `scans` 는 한 시험에 20,000 이하.
6. 만들 파일 하나만 쓴다(`out/tests.json`). 설명은 `purpose` 에만 쓴다.
