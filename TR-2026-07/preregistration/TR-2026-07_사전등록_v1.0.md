## 1. 질문

공장 설비 없이 바닥 · 장애물 · 자리 6곳 · 충전 스테이션 2대만 있는 18 x 12 m 시뮬레이션 실험장에서(물리값은 가정값, 실물 대조 없음), 적재 한도 · 역할이 다른 AMR 5대(3기종)가 같은 작업 목록을 처리할 때,

1. 운반을 끝낸 차를 **출발 위치로 돌려보내는 규칙(복귀)** 대신 **끝낸 자리에서 다음 작업을 받게 하는 규칙(재배차)** 을 쓰면 **운반 1건당 빈 주행 거리가 얼마나 달라지는가**(크기 측정).
2. 같은 150초 동안 **끝낸 운반 수가 줄지 않는가**(비열등 시험).
3. 그 크기는 같은 배치 파일에서 실험장을 다시 작성할 때마다 얼마나 흔들리는가.

**방향은 배치가 대부분 정한다.** 출발 위치(x = −7 m)는 싣는 열(x = −3.5 m)보다 바깥에 있어, 복귀 규칙은 내린 뒤 출발 위치까지 돌아가는 거리만큼 빈 주행이 길어진다. 이 편은 「재배차가 빈 주행을 줄이는가」를 시험하는 실험이 아니라, **이 실험장에서 그 크기와 흔들림을 재고 완료 수를 대가로 치르지 않는지를 시험하는** 실험이다.

## 2. 왜 가상 실험인가

- 같은 실험장 · 같은 작업 목록 · 같은 차에 규칙만 바꿔 나란히 돌릴 수 있다. 한 작성 안에서는 결과가 비트 단위로 재현된다(§4).
- 규칙끼리의 비교(주 결과)는 같은 시뮬레이터 안에서만 이루어진다. 빈 주행의 절대 거리 · 완료 수는 실험장 배치 · 차량 가정값(§10)에 달려 있어 현장 값을 말하지 않는다.
- 이 편은 실물 AMR · 실물 배차 시스템에 대해 아무것도 말하지 않는다.

## 5. 확인 실험의 입력

- **고정 배치 파일 1개**(`layout.json`, §9)에서 실험장을 **20번 새로 작성한다**(작성 k = 1…20). 작성은 앱의 작성 단계(`--qa-stage fleet-lab-author`)가 마법사 · 배치 · 대화 상자 · 저장을 거쳐 한다. 작성마다 물체 식별자가 새로 무작위로 붙는다(시드 없음 — 같은 20회를 다시 만들 수 없으므로 한 번에 모두 만들고 모두 보고한다).
- **「식별자 말고는 같다」를 실행기가 확인한다**: 작성된 프로젝트에서 모든 식별자를 같은 표지 하나로 바꾸고, 식별자를 열쇠로 쓰는 묶음은 순서 없는 묶음으로 보고, 저장 시각 · 형상 서명 · 서명 소금값을 지운 정규형의 sha256 이 모든 작성에서 같아야 한다(다르면 실행 무효, §8). 이 정규형은 「값이 같다」를 확인할 뿐 식별자끼리의 연결 관계까지 비교하지는 않는다. 개발 실행 4작성에서 모두 같았다.
- 작성 하나 = 반복 하나. 작성 안의 반복은 정보가 없으므로(§4) 하지 않는다. 다만 **첫 유효 작성**은 규칙마다 2번 돌려 결정성을 확인한다.
- 작성마다 결과가 달라지는 기전은 확인하지 않았다(식별자가 바뀌면 물리 모델의 물체 생성 순서 · 배차의 동률 순서 등이 함께 바뀐다). 이 편은 기전을 주장하지 않고 흔들림의 크기만 적는다.
- 개발 중 오염 금지: 실행 도구 개발 · 시험은 별도 출력 폴더의 개발 실행으로만 했다. 공식 실행의 작성 20회는 공식 실행에서 처음 만든다.

## 6. 설계

### 6-1. 규칙

작성마다 같은 프로젝트에서 공정 설정의 규칙 표시만 바꾼 사본을 만든다.
- **비교 대상(같은 조건)**: 복귀 · 재배차 · 공동 배차 — 규칙 표시만 다르다.
- **충전(확인용, 비교하지 않음)**: 재배차 + 차 5대에 배터리(용량 1 Wh, 이동 0.002 Wh/m, 25 % 아래면 충전 예약). **출발 위치 (−7, −4)** 의 차(V1)만 20 %에서 시작하고 나머지는 100 %. 차가 충전으로 빠지는 다른 조건이므로 완료 수 · 빈 주행을 다른 규칙과 비교하지 않고 P5 에만 쓴다.

### 6-2. 실행

물리 실행 자식 프로세스(`--physical-study-child`), 시뮬레이션 150초, 고정 간격 0.05초, 빠른 모드. 한 실행 = 한 프로세스. 4개씩 병렬(결과는 병렬 수와 무관하다고 보고, 결정성 확인으로 본다). 결과 파일이 생기지 않은 실행(비정상 종료 · 시간 한도)은 **같은 프로젝트로 최대 2번 다시 실행**하고, 모든 시도를 남긴다(마지막 시도를 센다).

### 6-3. 측정 (실행마다)

| 측정 | 정의 |
| --- | --- |
| 완료 수 | 150초 안에 내리기가 끝난 운반 수(`completedTransfers`) |
| 빈 주행 합 | 함대 계기 `fleet.emptyTravelMeters`(§3) |
| **1건당 빈 주행** | 빈 주행 합 ÷ 완료 수 |
| 60초 안 완료 | 완료 시각 ≤ 60 s 인 건수 |
| 평균 운반 시간 | 싣기 시작(첫 Loaded 표본 − 2.5 s)부터 내리기 끝까지의 평균 |
| 동시 이동 | 10초 이후 1초 표본마다 수평 속도 > 0.05 m/s 인 차 수 — 최솟값 · 3대 이상인 비율 |
| 차끼리 접촉 | `amrPeerContactCount` |
| 충전 | 배터리 낮은 차(V1, 출발 (−7, −4))의 도킹 표본 수 · 한 충전기 동시 예약 표본 수 |
| 거절 | 사유별 합(역할 불일치 · 적재 초과 등) |
| 최고 속도 | 차별 기록 최고 속도 |

## 7. 가설 · 사전 예측 · 판정선 (실행 전에 숫자로 고정)

**주 가설** — 이 실험장에서 끝낸 자리 재배차의 운반 1건당 빈 주행은 복귀보다 짧고(크기 측정), 같은 150초에 끝낸 운반 수는 복귀보다 적지 않다(비열등).

주 지표: 유효한 작성 k 마다 **r_k = (재배차 빈 주행 ÷ 재배차 완료 수) ÷ (복귀 빈 주행 ÷ 복귀 완료 수)**. 기록된 2진 부동소수 값의 정확한 분수로 계산한다. 재배차 완료 0 이면 r_k = +∞(1 이상으로 셈). 중앙값은 짝수 개면 가운데 두 값의 평균. 비율 판정은 정수식(예: 「x/n ≥ 80 %」 = 5x ≥ 4n)으로 하고, 분모 n 은 유효한 작성 수다.

**재현 예측(예비 관찰을 보고 세움)**

| 번호 | 예측 | 판정선 | 예비 값 |
| --- | --- | --- | --- |
| P1 | r_k 의 중앙값 ≤ 0.95 | 초과면 [틀림] | 8작성 0.845~0.924 |
| P2 | r_k < 1 인 작성이 80 % 이상 | 미만이면 [틀림] | 8/8 |
| P3 | 재배차 완료 수 ≥ 복귀 완료 수인 작성이 70 % 이상 | 미만이면 [틀림] | 6/8 — 판정선에 가깝다. 판정선은 v0.2 값 그대로 두었다 |

**새 예측 · 확인**

| 번호 | 예측 | 판정선 |
| --- | --- | --- |
| P4 | 세는 모든 실행(유효 작성의 4규칙 + 결정성 확인 2회째)에서 시뮬레이션 안의 차끼리 접촉 0 | 1건이라도 있으면 [틀림] |
| P5 | 충전 규칙: 모든 유효 작성에서 배터리 낮은 차(V1, 출발 (−7, −4))가 도킹하고(도킹 표본 > 0) 한 충전기 동시 예약 표본이 0 | 하나라도 벗어나면 [틀림] |

**반증 조건**

| 번호 | 조건 | 틀린 것으로 적는 주장 |
| --- | --- | --- |
| F1 | r_k 의 중앙값 ≥ 1.00 | 「재배차의 1건당 빈 주행이 복귀보다 짧다」 — 배치상 거의 일어나지 않을 조건이다(§1) |
| F2 | 재배차 완료 수 < 복귀 완료 수인 작성이 절반 초과(2x > n) | 「재배차는 완료 수를 줄이지 않는다」 |

- P1 [틀림] 이고 F1 이 걸리지 않으면(0.95 < 중앙값 < 1.00): 「줄지만 예측한 크기(5 % 이상)는 아니다」로 적는다.
- 합격/불합격 없음. **결과는 어느 쪽이든 공개한다.** 틀린 예측은 고치지 않는다. 분모가 20 미만이면(무효 작성이 있으면) 비율 없이 분자/분모로 적는다.

## 8. 실행 무효 기준 · 재시도 · 탐색적 보고

**실행 시작 전 거부**: 배치 파일 · 실행기 · 표 · 독립 검산 · 공개본 변환 스크립트 가운데 하나라도 sha256 이 고정값(§9)과 다르거나 제품 커밋이 40자 16진수가 아니면 실행기가 시작하지 않는다.

**좋은 실행**: 종료 코드 0 · 결과 상태 `horizon_reached` · 오류 없음 · 결과 · 진단 · 로그 파일이 있고 측정이 끝난 실행.
**유효한 작성**: 작성 단계 PASS, 그 작성의 4규칙 실행(1회째)이 모두 좋은 실행, 복귀 완료 ≥ 1.
**실행 전체 무효**(모든 판정을 「무효」로 적는다): ① 작성된 프로젝트의 정규형 sha256 이 하나가 아님 ② 첫 유효 작성의 2회 실행이 어느 규칙에서든 완료 수 · 빈 주행 합 · 완료 시각 목록 중 하나라도 다름 ③ 무효 작성이 2개 초과 ④ 작성 단계가 PASS 인 작성의 실행 행이 하나라도 없음(기대 실행 수 = 4 × PASS 작성 수 + 4).
**재시도**: 무효 작성은 다시 만들지 않고 분모에서 뺀다. 결과가 없는 실행은 같은 프로젝트로 최대 2번 다시 실행한다(§6-2). 실행 전체가 무효면 새 폴더에서 처음부터 다시 하되, 같은 원인으로 최대 2번이고 모든 시도를 공개한다. 무효 · 중단 폴더는 지우지 않고 `_invalid/<시각>_<원인>/` 로 옮긴다.
**바깥 감시 · 양성 대조**: 공식 실행 전에 같은 실행 파일로 개발 실행(작성 2회)을 끝까지 돌려 표 · 독립 검산 · 공개본 변환까지 통과함을 확인한다(양성 대조). 공식 실행 중 작성 단계가 연속 2회 PASS 가 아니면 멈추고 원인을 적는다.

**탐색적 보고(가설 없음 — 주 결과와 분리)**
- E1 공동 배차 ÷ 재배차의 1건당 빈 주행(중앙값), 공동 배차가 재배차와 완료 시각까지 같은 작성 수.
- E2 개발 계획의 움직임 목표(평균 운반 ≤ 20 s · 60 s 에 8건 · 10 s 뒤 늘 3대 이상 이동)과 견준 규칙별 값(중앙값 · 최소 · 최대).
- E3 거절 사유별 합(역할 불일치 · 적재 초과), 기종별 최고 속도.

## 11. 주장하지 않는 것 · 한계

- 시뮬레이션이다. 실물 AMR · 실물 배차 시스템과 대조한 결과는 없다.
- 실험장 하나 · 한 방향 작업 목록 하나 · 차 5대 · 150초다. **효과의 방향은 출발 위치 배치로 대부분 정해진다**(§1). 다른 배치 · 작업 흐름(예: 양방향)에서 크기 · 방향은 다를 수 있다(§4 의 양방향 시도는 한 번뿐이다).
- **실험장은 재배차 규칙의 성적을 보며 F4~F8 에 걸쳐 고쳐졌다**(§4). 규칙끼리 공정하게 조정된 실험장이 아니다.
- 반복 단위는 「다시 작성한 실험장」이다. 무작위 표본의 통계적 불확실성과 같지 않다. 신뢰 구간을 내지 않고 분포(중앙값 · 최소 · 최대 · 작성별 값)를 적는다. 흔들림의 기전은 주장하지 않는다(§5).
- 빈 주행은 엔진 계기 값이다(§3 의 정의). 독립 검산은 같은 결과 파일에서 다시 셀 뿐, 계기 자체를 다른 방법으로 재지 않는다.
- 물리값(마찰 · 짐 치수 · 바퀴 · 모터)은 가정값이다. 바퀴 접촉 모델은 이 편 직전(F8)에 바꿨다.
- 우분투 한 기계 · 한 실행 파일의 결과다.
- 「차끼리 접촉 0」(P4)은 시뮬레이션 안의 접촉 계기 값이다. 안전성 주장이 아니다.
- **생성형 AI 관여**: 실험장 · 배차 · 물리 코드, 실행 도구, 이 문안 작성과 교차 검토에 LLM 코딩 에이전트가 관여했다. 코드를 사람이 줄 단위로 검수한 적은 없다.
